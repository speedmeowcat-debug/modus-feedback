# Допущения

ТЗ (раздел 5) просит фиксировать существенные допущения и объяснять их влияние.

| Допущение | Почему принято | Влияние | Как изменить |
| --- | --- | --- | --- |
| Подача обращений не анонимная | ТЗ (2.6): анонимность необязательна. Без автора невозможны уточнения и показ итога, то есть ломается основной сценарий | Сотрудник может не решиться сообщить о чувствительной проблеме | Отдельный тип «конфиденциальное обращение»: автора видит только назначенный доверенный сотрудник |
| Подразделения и принадлежность условных ролей к ним заданы нами | В датасете есть только условные роли авторов и ответственных | Обзор руководителя и аналитика по подразделениям в демо отражают наше распределение | Справочник подразделений и пользователи редактируются в настройках; в целевой версии приходят из Битрикс24 |
| Роли доступа условных ответственных выбраны по названию | «Руководитель …» получает роль руководителя, «Ответственный за …» и специалисты получают роль ответственного | Руководители без подразделения («Руководитель направления», «Руководитель подразделения») видят только обращения, где участвуют | Роль и подразделение меняет администратор |
| Все даты демо-набора синтетические | В датасете дат нет, а для сроков и времени первого ответа они нужны (датасет, сценарий 6: «при добавлении тестовых дат») | Показатели времени на демо-наборе не отражают реальность | Даты помечены в базе и в интерфейсе; в аналитике есть режим «Без демо-набора» |
| У обращений датасета нет заголовка | В датасете есть тип, категория и текст, заголовка нет | В списке показывается начало текста, в карточке «тип: категория» | Для новых обращений заголовок обязателен |
| Итог рассмотрения взят из датасета только там, где он назван | Для A-004, A-008 («Пример результата: …») и A-017 («Пример мотивированного ответа: …»). Для A-018 итога в датасете нет | У A-018 статус «Закрыто» без текста итога | Поле «Пример дальнейшего действия» сохранено для всех 20 обращений и видно обрабатывающим |
| Правила маршрутизации выведены из датасета | Категория → условный ответственный; для «Корпоративной среды» ответственный зависит от типа | Правила воспроизводят назначения датасета (проверяется тестом), но не являются регламентом компании | Правила редактируются в настройках |
| Приоритет назначает обрабатывающий | В основном сценарии ТЗ автор приоритет не указывает | Новое обращение создаётся со средним приоритетом | Ответственный, руководитель или администратор меняют приоритет в карточке |
| Срок рассмотрения 14 календарных дней, первый ответ 24 часа | Регламента в ТЗ нет | Индикаторы просрочки на демо условны | Срок задаётся по категориям, норма первого ответа в параметрах |
| Один часовой пояс: Павлодар, UTC+5 | Компания работает в одном регионе | Даты показываются одинаково для всех | Константа в `src/lib/format.ts` |
| Руководитель видит все обращения своего подразделения | ТЗ (2.2): руководители рассматривают обращения и назначают ответственных | Обращение о руководителе увидит сам руководитель | Вместе с конфиденциальными обращениями: маршрут в обход руководителя |
| Обращение относится к одному подразделению или ни к одному | Упрощение для MVP | Межотдельную проблему видит руководитель одного подразделения и ответственный по категории | Список затронутых подразделений вместо одного значения |
