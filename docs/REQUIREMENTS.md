# Матрица соответствия требованиям

Источники: «ТЗ на разработку системы обратной связи и предложений сотрудников» и «Датасет» (оба документа прочитаны полностью). Номера разделов в скобках относятся к ТЗ.

Приоритеты: **Must** — без этого основной сценарий не работает; **Should** — заметно повышает ценность MVP; **Later** — следующий этап.

## Функции

| Требование | Приоритет | Статус | Где в продукте | Критерий готовности |
| --- | --- | --- | --- | --- |
| Выбор категории, описание, предполагаемое решение, материалы (2.3, шаги 1–2) | Must | Готово | Форма «Новое обращение» | Произвольное обращение сохраняется; ошибки показываются у полей, введённое не теряется |
| Регистрация и передача ответственному по правилам (2.3, шаг 3) | Must | Готово | Сервис маршрутизации, «Настройки → Маршрутизация» | Обращение получает номер и ответственного; причина назначения записана в истории |
| Альтернатива при отсутствии ответственного (Датасет, сценарий 2) | Must | Готово | Резервный ответственный, флаг «Отсутствует» | При отсутствии ответственного обращение уходит резервному с объяснением |
| Рассмотрение, фиксация решения и действий (2.3, шаг 4) | Must | Готово | Карточка обращения, блок «Следующий шаг» | Итог обязателен для «Реализовано», причина обязательна для «Отклонено» |
| Автор отслеживает статус и видит результат (2.3, шаг 5) | Must | Готово | «Мои обращения», карточка | Автор видит статус, ответственного, историю, итог или причину отказа |
| Сохранение для анализа (2.3, шаг 6) | Must | Готово | PostgreSQL, таблицы `tickets`, `ticket_events` | Все действия остаются в истории, аналитика считается по базе |
| Управление статусами и сроками (2.4) | Must | Готово | Семь статусов, срок по категории, ручное изменение срока | Недопустимый переход отклоняется сервером |
| Комментарии и запрос уточнений (2.4) | Must | Готово | История, «Запросить уточнение», «Нужен ваш ответ» | После ответа автора обращение возвращается в прежний статус |
| Разграничение доступа по ролям (1.3, 2.6) | Must | Готово | Проверки в сервисах, `scopeSql` | Чужое обращение недоступно по прямой ссылке; тесты на каждую роль |
| Категоризация по подразделениям, направлениям, типам (2.4) | Should | Готово | Тип, категория, подразделение в обращении | Фильтры по всем трём признакам |
| Поиск, фильтрация, история (2.4) | Should | Готово | Списки обращений | Поиск по номеру и тексту; фильтры по статусу, типу, категории, подразделению, приоритету, сроку |
| Контроль просрочек (Датасет, сценарий 5) | Should | Готово | Индикаторы в списках, фильтр «Просроченные» | Просроченные и оставшиеся без первого ответа выделены |
| Уведомления автора и ответственных (2.4) | Should | Частично | Уведомления внутри приложения | Назначение, смена статуса, уточнение, комментарий. Почта и мессенджеры: Later |
| Аналитика по категориям, повторам, результатам (2.4, 2.7) | Should | Готово | «Аналитика» | Количество по типам, доля завершённых, время первого ответа, похожие обращения |
| Управление категориями, настройками, правилами (2.2) | Should | Готово | «Настройки» | Изменения применяются к новым обращениям и пишутся в журнал |
| Анонимная подача (2.6) | Later | Не делали | — | Требование необязательное; см. допущения в `ASSUMPTIONS.md` |
| Интеграции с Битрикс24 и 1С (3.4) | Later | Описано | `ARCHITECTURE.md`, раздел «Интеграции» | Цель, состав данных, вопросы для уточнения |
| Клиентская обратная связь, NPS, опросы (2.2, 2.4) | Later | Описано | `ROADMAP.md` | ТЗ относит к следующим этапам |

## Показатели из ТЗ (2.7)

| Показатель | Как считается |
| --- | --- |
| Доля рассмотренных обращений | Статусы «Реализовано», «Отклонено», «Закрыто» к общему числу |
| Время до первого ответа | От создания до первого действия обрабатывающего (смена статуса, уточнение, публичный комментарий) |
| Доля обращений с зафиксированным результатом | Обращения с непустым итогом к общему числу |
| Количество реализованных улучшений | Обращения в статусе «Реализовано» |

Целевые значения не задаются: по ТЗ они «требуют отдельного определения».

## Роли и потоки

| Роль | Основная задача | Путь |
| --- | --- | --- |
| Сотрудник | Сообщить и узнать, чем закончилось | Новое обращение → номер → уведомления → итог |
| Ответственный | Разобрать свою очередь в срок | Очередь → карточка → уточнение или решение |
| Руководитель | Контролировать подразделение | Обзор → просроченные → передача ответственному → аналитика |
| Администратор | Настроить процесс | Категории и сроки → правила → пользователи → параметры |
